# Plan: แก้ให้ ui มี text ด้วย

รหัสงาน: `T-20261108-65b6c3` อ้างอิงจาก `spec.md`

## ไฟล์ที่จะแก้

ยังระบุไม่ได้ เพราะไม่ทราบว่า UI หน้าจอหรือคอมโพเนนต์ใดที่ต้องเพิ่มข้อความ และยังไม่ได้เห็นค่า `allowed_paths` ใน `policy.toml` จึงไม่เดารายชื่อไฟล์

สิ่งที่ต้องทำก่อนกำหนดรายการไฟล์:

- ได้คำตอบจากผู้ขอว่า UI ส่วนใดที่เกี่ยวข้อง
- อ่าน `policy.toml` เพื่อยืนยันว่าไฟล์ที่จะแก้อยู่ใน `allowed_paths`
- ค้นหาไฟล์คอมโพเนนต์ของ UI ส่วนนั้นในรีโพ แล้วจึงสรุปรายการไฟล์

## ลำดับงาน

ลำดับต่อไปนี้เป็นกรอบเบื้องต้น ขั้นที่ 1 ต้องเสร็จก่อนจึงจะเริ่มขั้นถัดไปได้

1. **ขอข้อมูลจากผู้ขอ** (บล็อกงานทั้งหมด) ให้ตอบ:
   - UI หน้าจอหรือคอมโพเนนต์ใดที่ต้องเพิ่มข้อความ
   - เนื้อหาข้อความและภาษาที่ใช้
   - ตำแหน่งและรูปแบบการแสดงข้อความ
   - มีเกณฑ์ตรวจรับหรือภาพตัวอย่างอ้างอิงหรือไม่
   - ระบบต้องรองรับหลายภาษาหรือไม่
2. อ่าน `policy.toml` และสำรวจโค้ด UI ส่วนที่เกี่ยวข้อง เพื่อดูว่าปัจจุบันแสดงอะไรอยู่ และระบบจัดการข้อความ (เช่น ไฟล์แปลภาษา) อย่างไร
3. ปรับ `plan.md` ส่วน "ไฟล์ที่จะแก้" ให้เป็นรายการไฟล์จริง และตรวจว่าอยู่ใน `allowed_paths`
4. เพิ่มข้อความใน UI ตามที่ผู้ขอกำหนด โดยจำกัดเฉพาะการเพิ่มข้อความ ไม่เปลี่ยนโครงสร้าง ดีไซน์ หรือพฤติกรรมอื่น
5. ทดสอบตามหัวข้อ "วิธีพิสูจน์" และตรวจว่า UI ส่วนอื่นไม่เปลี่ยน
6. ส่งผลให้ผู้ขอตรวจรับ

## ความเสี่ยง

- **ข้อกำหนดไม่ชัด:** ถ้าเริ่มทำโดยไม่มีคำตอบ อาจเพิ่มข้อความผิดที่หรือผิดเนื้อหา รับมือโดยไม่เริ่มแก้โค้ดจนกว่าผู้ขอตอบครบ
- **ข้อความล้นหรือเลย์เอาต์พัง:** โดยเฉพาะข้อความยาวหรือหน้าจอเล็ก รับมือโดยทดสอบหลายขนาดหน้าจอและขนาดตัวอักษร
- **การแสดงผลภาษาไทย:** วรรณยุกต์และสระซ้อนอาจถูกตัดขอบ รับมือโดยตรวจ line-height และฟอนต์ในจุดที่เพิ่มข้อความ
- **ข้อความว่างหรือไม่มีข้อมูล:** ต้องรู้ว่าจะแสดงอะไรแทน รับมือโดยถามผู้ขอและทดสอบกรณีนี้
- **หลายภาษา:** ถ้าระบบรองรับหลายภาษา ข้อความที่เพิ่มต้องมีครบทุกภาษา ไม่เช่นนั้นบางภาษาจะแสดงว่างหรือแสดงคีย์ รับมือโดยยืนยันเรื่องนี้กับผู้ขอก่อน
- **แก้เกินขอบเขต:** รับมือโดยตรวจ diff ว่าแตะเฉพาะไฟล์ใน `allowed_paths` และเฉพาะส่วนที่เกี่ยวข้อง

## วิธีพิสูจน์

เนื่องจากเกณฑ์ยอมรับยังไม่ครบ รายการนี้เป็นกรอบเบื้องต้นและต้องปรับเมื่อได้ข้อมูลจากผู้ขอ

- **แสดงข้อความถูกต้อง:** เปิด UI ส่วนที่ระบุ แล้วตรวจว่าข้อความตรงกับเนื้อหา ตำแหน่ง และรูปแบบที่ผู้ขอกำหนด (ถ้าโปรเจกต์มีชุดทดสอบ UI ให้เพิ่มการทดสอบที่ตรวจข้อความนี้ ชนิดการทดสอบรอดูจากโครงสร้างโปรเจกต์)
- **อ่านชัดเจนและเลย์เอาต์ไม่เสีย:** ตรวจด้วยตาและภาพหน้าจอก่อน/หลัง ที่หลายขนาดหน้าจอและขนาดตัวอักษร รวมกรณีข้อความยาว
- **ภาษาไทยแสดงถูกต้อง:** ตรวจว่าวรรณยุกต์และสระซ้อนไม่ถูกตัด
- **กรณีข้อความว่าง:** ตรวจว่าแสดงผลตามที่ผู้ขอกำหนด
- **ส่วนอื่นไม่เปลี่ยน:** เทียบภาพหน้าจอก่อน/หลังของส่วนที่ไม่เกี่ยวข้อง และรันชุดทดสอบเดิมของโปรเจกต์ (ถ้ามี) ให้ผ่านเหมือนก่อนแก้
- **ขอบเขตการแก้:** ตรวจ `git diff` ว่าแตะเฉพาะไฟล์ที่ระบุและอยู่ใน `allowed_paths`

**สิ่งที่ยังไม่รู้:** ไฟล์ที่ต้องแก้ ค่า `allowed_paths` ชุดทดสอบที่โปรเจกต์มี และเกณฑ์ตรวจรับจากผู้ขอ
