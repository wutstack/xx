# Plan: react app three.js for 3d example

รหัสงาน: `T-20261108-2cc7b2` อ้างอิงจาก `spec.md`

## ไฟล์ที่จะแก้

ยังไม่ทราบรายการ `allowed_paths` ใน `policy.toml` เพราะข้อมูลที่ได้รับไม่มีไฟล์นี้ จึงยังยืนยันไม่ได้ว่าไฟล์ด้านล่างอยู่ในขอบเขตที่อนุญาต ต้องตรวจกับ `policy.toml` ก่อนลงมือ

รายการไฟล์ด้านล่างเป็นข้อเสนอเบื้องต้น โดยสมมติว่าใช้ three.js โดยตรง กับ Vite และ JavaScript ซึ่งทั้งสามข้อยังรอมนุษย์ยืนยันตาม `spec.md` หัวข้อ "เรื่องที่ต้องให้มนุษย์ตัดสิน" ข้อ 1–3 หากคำตอบต่างไป รายการไฟล์จะเปลี่ยนตาม (เช่น เปลี่ยนนามสกุลเป็น `.tsx` หรือใช้ `@react-three/fiber`)

ไฟล์ที่จะสร้างใหม่ (ยังไม่ทราบไดเรกทอรีปลายทางที่ policy อนุญาต):
- `package.json` — dependency (`react`, `react-dom`, `three`) และสคริปต์รัน
- `index.html` — จุดเข้าของหน้าเว็บ
- `vite.config.js` — ค่าตั้งของเครื่องมือสร้างโปรเจกต์ (ถ้าเลือก Vite)
- `src/main.jsx` — mount แอป React
- `src/App.jsx` — คอมโพเนนต์หลักที่วางพื้นที่แสดงฉาก
- `src/components/ThreeScene.jsx` — คอมโพเนนต์ React ที่ผูก canvas กับฉาก และจัดการ mount/unmount
- `src/three/createScene.js` — ส่วน three.js ล้วน: สร้าง scene, camera, light, mesh, renderer และฟังก์ชันคืนทรัพยากร
- `README.md` — วิธีติดตั้ง รันตัวอย่าง และเวอร์ชัน Node ที่ต้องใช้ (ยังไม่ทราบเวอร์ชัน)
- `.gitignore` — ไม่รวม `node_modules` และผลลัพธ์การ build

ไฟล์ที่มีอยู่เดิมและจะแก้: ยังไม่ทราบ เพราะไม่มีข้อมูลโครงสร้างโปรเจกต์ปัจจุบัน และ git status แสดงเพียงไฟล์ `sdlc.toml` กับ `sdlc.example.toml` ที่ยังไม่ถูกติดตามอยู่นอกโฟลเดอร์งานนี้

## ลำดับงาน

1. **ยืนยันข้อตัดสินใจที่ค้างอยู่:** วิธีใช้ three.js, ภาษา, เครื่องมือสร้างโปรเจกต์, ชนิดและจำนวนตัวอย่าง, การโต้ตอบ/แอนิเมชัน และตรวจ `allowed_paths` ใน `policy.toml` ถ้ายังไม่ได้คำตอบ ให้ใช้ข้อสมมติเบื้องต้นข้างต้นและบันทึกไว้ใน README
2. **สร้างโครงโปรเจกต์:** `package.json`, `index.html`, ค่าตั้งเครื่องมือสร้าง, `.gitignore` แล้วตรวจว่าติดตั้ง dependency ได้
3. **เขียนส่วน three.js ล้วน** ใน `src/three/createScene.js`: สร้าง scene, กล้อง, แสง, วัตถุอย่างน้อยหนึ่งชิ้น, renderer และลูปวาดภาพ โดยคืนฟังก์ชัน `dispose` ที่ยกเลิกลูป คืน geometry, material, renderer และถอด canvas ออก
4. **เขียนคอมโพเนนต์ React** `ThreeScene.jsx`: สร้างฉากใน effect, ส่ง container ให้ส่วน three.js, เรียก `dispose` ใน cleanup, จัดการ resize
5. **ต่อเข้ากับแอป:** `main.jsx` และ `App.jsx` แล้วลองเปิดในเบราว์เซอร์
6. **จัดการกรณีขอบ:** ตรวจ WebGL ไม่รองรับแล้วแสดงข้อความแจ้ง (ถ้อยคำรอการยืนยัน), ตรวจพฤติกรรมใน StrictMode ว่าไม่เกิด canvas หรือลูปซ้อน
7. **เขียน README:** ขั้นตอนติดตั้ง รัน และคำอธิบายสั้น ๆ ว่า three.js เชื่อมกับ React อย่างไร รวมข้อสมมติที่ยังรอยืนยัน
8. **ตรวจตามหัวข้อ "วิธีพิสูจน์"** และบันทึกผลตามจริง รวมข้อที่ตรวจไม่ได้

## ความเสี่ยง

| ความเสี่ยง | วิธีรับมือ |
|---|---|
| ข้อมูลความต้องการมีเพียงบรรทัดเดียว ทำให้ตีความผิดจากที่ผู้ใช้ต้องการ | ทำฉากขนาดเล็กที่สุดตามขอบเขต ระบุข้อสมมติใน README และรอการยืนยันก่อนขยาย |
| ไม่ทราบ `allowed_paths` ใน `policy.toml` ไฟล์ที่เสนออาจอยู่นอกขอบเขต | ตรวจ `policy.toml` ก่อนสร้างไฟล์ใด ๆ และปรับรายการไฟล์ให้อยู่ในขอบเขต |
| React StrictMode เรียก effect สองครั้ง ทำให้เกิด canvas หรือลูปวาดภาพซ้อน | ให้ cleanup เรียก `dispose` ครบ (ยกเลิก `requestAnimationFrame`, ถอด canvas, `renderer.dispose()`) และทดสอบใน development |
| memory leak จาก geometry/material/texture ที่ไม่ถูกคืน | รวมการคืนทรัพยากรไว้ในฟังก์ชันเดียว และตรวจด้วย `renderer.info.memory` |
| เบราว์เซอร์ไม่รองรับ WebGL ทำให้แอปล่ม | ครอบการสร้าง renderer ด้วย try/catch และแสดงข้อความแจ้ง |
| เวอร์ชัน Node หรือเวอร์ชันแพ็กเกจไม่ตรง ทำให้ติดตั้งไม่ผ่าน | ระบุเวอร์ชัน Node และเวอร์ชัน dependency ใน `package.json` และ README (ยังไม่ทราบเวอร์ชันที่เหมาะสม ต้องตรวจตอนติดตั้ง) |
| ตัดสินใจเลือก three.js โดยตรงหรือ `@react-three/fiber` ผิด ทำให้ต้องเขียนใหม่ | ยืนยันข้อนี้เป็นอันดับแรกในลำดับงานข้อ 1 |
| pixel ratio สูงทำให้ภาพช้า | จำกัดค่า pixel ratio ที่ระดับหนึ่ง (ค่าที่เหมาะสมยังไม่ทราบ ต้องให้มนุษย์ยืนยัน) |

## วิธีพิสูจน์

ยังไม่มีเฟรมเวิร์กทดสอบหรือเป้าหมายตัวเลข (เฟรมเรต ขนาดบันเดิล เบราว์เซอร์ที่รองรับ) ตาม `spec.md` จึงใช้การตรวจที่ทำซ้ำได้ตามเกณฑ์ยอมรับใน `intent.md`:

| เกณฑ์ยอมรับ | วิธีตรวจ |
|---|---|
| ติดตั้งและรันได้ ไม่มีข้อผิดพลาดในคอนโซล | รันคำสั่งติดตั้งและรันตาม README บนเครื่องที่สะอาด เปิดหน้าเว็บ แล้วตรวจคอนโซลว่าไม่มี error หรือ warning จาก React/three.js |
| หน้าเว็บแสดงฉาก 3 มิติที่มีวัตถุอย่างน้อยหนึ่งชิ้น | เปิดดูด้วยตา และเขียนการทดสอบอัตโนมัติ (ถ้าตกลงใช้เฟรมเวิร์ก เช่น Vitest) ตรวจว่ามี `<canvas>` ใน container หลัง mount |
| โค้ดแยกส่วน three.js จาก React อ่านเข้าใจได้ | ตรวจว่า `createScene.js` ไม่ import React และ `ThreeScene.jsx` ไม่สร้างวัตถุ three.js โดยตรง ยกเว้นการเรียก `createScene` และ `dispose` |
| คืนทรัพยากรเมื่อถอดคอมโพเนนต์ | ทดสอบ mount แล้ว unmount: จำนวน canvas ใน DOM เป็น 0, ลูปวาดภาพหยุด, ค่า `renderer.info.memory.geometries` และ `textures` กลับเป็น 0 (ตรวจก่อน dispose renderer หรือด้วย mock) |
| ไม่มี canvas หรือลูปซ้อนใน StrictMode | รันใน development ที่เปิด StrictMode แล้วตรวจว่ามี canvas เดียวและมีลูปวาดภาพเดียว |
| กรณี WebGL ไม่รองรับ | จำลองด้วยการ mock ให้สร้าง context ล้มเหลว แล้วตรวจว่าแอปไม่ล่มและแสดงข้อความแจ้ง |
| ปรับขนาดหน้าต่าง | ปรับขนาดหน้าต่างด้วยมือ ตรวจว่าภาพไม่บิดเบี้ยวและ canvas ปรับตามพื้นที่ |
| มี README บอกวิธีรัน | ให้ผู้ที่ไม่เคยเห็นโปรเจกต์ทำตามขั้นตอนใน README จนแอปเปิดได้ |

สิ่งที่ยังพิสูจน์ไม่ได้จนกว่ามนุษย์จะตัดสินใจ: การโต้ตอบและแอนิเมชัน, เป้าหมายเฟรมเรต, ขนาดบันเดิล, เบราว์เซอร์และมือถือที่ต้องรองรับ, พฤติกรรมเมื่อแท็บอยู่เบื้องหลัง
