# Spec: react app three.js for 3d example

รหัสงาน: `T-20261108-2cc7b2` อ้างอิงจาก `intent.md`

## พฤติกรรมที่ต้องมี

ข้อมูลที่ได้รับมีเพียงบรรทัดเดียว พฤติกรรมด้านล่างจึงเป็นข้อกำหนดขั้นต่ำที่อนุมานจาก `intent.md` ส่วนรายละเอียดอื่นที่ไม่ได้ระบุถูกยกไปไว้ในหัวข้อ "เรื่องที่ต้องให้มนุษย์ตัดสิน"

**การรันและการเปิดแอป**
- เมื่อติดตั้ง dependency และรันตามคำสั่งใน README แล้ว แอป React เปิดได้ในเบราว์เซอร์โดยไม่มีข้อผิดพลาดในคอนโซล
- README ระบุขั้นตอนติดตั้งและรันในเครื่องอย่างชัดเจน (ยังไม่ทราบเครื่องมือสร้างโปรเจกต์และตัวจัดการแพ็กเกจ)

**การแสดงฉาก 3 มิติ**
- หน้าเว็บแสดงฉาก 3 มิติอย่างน้อยหนึ่งฉาก ประกอบด้วย กล้อง แสง และวัตถุ 3 มิติอย่างน้อยหนึ่งชิ้นที่มองเห็นได้
- ฉากแสดงผลในพื้นที่ canvas ที่ถูกสร้างและผูกเข้ากับคอมโพเนนต์ React

**โครงสร้างโค้ด**
- ส่วนที่เกี่ยวกับ three.js แยกจากส่วนประกอบ React อย่างอ่านเข้าใจได้ เพื่อให้ผู้อ่านเห็นวิธีเชื่อม three.js เข้ากับ React
- ผู้ที่ได้รับโค้ดเปิดดูตัวอย่างแล้วเข้าใจวิธีเชื่อมได้จากโค้ดและ README

**การคืนทรัพยากร**
- เมื่อคอมโพเนนต์ถูกถอดออกหรือเลิกใช้ มีการคืนทรัพยากรของ three.js ได้แก่ renderer, geometry, material และยกเลิกลูปการวาดภาพ (ถ้ามี)
- ไม่มีการเพิ่ม canvas ซ้ำเมื่อคอมโพเนนต์ถูกสร้างใหม่

**สิ่งที่ไม่อยู่ในขอบเขต (ข้อสมมติเบื้องต้น รอการยืนยัน)**
- ไม่มีระบบผู้ใช้ ฐานข้อมูล หรือเซิร์ฟเวอร์ฝั่งหลังบ้าน
- ไม่ปรับแต่งประสิทธิภาพขั้นสูง
- ไม่ดีพลอยขึ้นระบบจริง

## กรณีขอบ

ข้อมูลไม่ได้ระบุกรณีขอบไว้ รายการนี้เป็นกรณีที่ควรจัดการหรืออย่างน้อยต้องตัดสินใจ โดยพฤติกรรมที่คาดหวังยังต้องให้มนุษย์ยืนยัน

- **เบราว์เซอร์ไม่รองรับ WebGL หรือสร้าง context ไม่ได้:** แอปไม่ควรล่ม ควรแสดงข้อความแจ้งผู้ใช้ (รูปแบบข้อความยังไม่ทราบ)
- **ขนาดหน้าต่างเปลี่ยน:** ฉากควรปรับขนาด canvas และอัตราส่วนกล้องตามพื้นที่แสดงผล (ยังไม่ทราบว่าต้องรองรับมือถือหรือไม่)
- **คอมโพเนนต์ถูก mount/unmount ซ้ำ (รวมถึง React StrictMode ใน development ที่เรียก effect สองครั้ง):** ต้องไม่เกิด canvas ซ้อน ลูปวาดภาพซ้อน หรือ memory leak
- **หน้าจอความละเอียดสูง (device pixel ratio สูง):** ยังไม่ทราบว่าต้องจำกัดค่า pixel ratio หรือไม่
- **แท็บอยู่เบื้องหลัง:** ยังไม่ทราบว่าต้องหยุดลูปวาดภาพหรือไม่
- **อินพุตจากผู้ใช้ (ถ้ามีการโต้ตอบ):** ยังไม่ทราบว่ามีการโต้ตอบหรือไม่ จึงยังกำหนดพฤติกรรมไม่ได้
- **การติดตั้ง dependency ล้มเหลวหรือเวอร์ชัน Node ไม่ตรง:** README ควรระบุเวอร์ชัน Node ที่ต้องใช้ (ยังไม่ทราบเวอร์ชัน)

## เรื่องที่ต้องให้มนุษย์ตัดสิน

1. **วิธีใช้ three.js:** ใช้ three.js โดยตรง หรือผ่านไลบรารีครอบ เช่น `@react-three/fiber` (มีผลต่อโครงสร้างโค้ดและวิธีคืนทรัพยากร)
2. **ภาษา:** JavaScript หรือ TypeScript
3. **เครื่องมือสร้างโปรเจกต์:** เช่น Vite หรืออื่น ๆ และตัวจัดการแพ็กเกจ
4. **จำนวนและชนิดของตัวอย่าง:** ต้องการฉากเดียวหรือหลายฉาก และเป็นวัตถุแบบใด
5. **การโต้ตอบและแอนิเมชัน:** ต้องมีการหมุนกล้องด้วยเมาส์ แอนิเมชัน หรือไม่
6. **วัตถุประสงค์และผู้ใช้:** ใช้เรียนรู้ ใช้เป็นต้นแบบ หรือใช้สาธิต และกลุ่มผู้ใช้เป็นใคร
7. **ตัวเลขที่วัดได้:** ต้องกำหนดเป้าหมายเฟรมเรต ขนาดบันเดิล หรือเบราว์เซอร์ที่ต้องรองรับหรือไม่ (ยังไม่มีข้อมูล)
8. **ขอบเขตที่ไม่ทำ:** ยืนยันข้อสมมติว่าไม่ทำระบบระดับใช้งานจริง การปรับแต่งประสิทธิภาพขั้นสูง และการดีพลอย
9. **พฤติกรรมเมื่อไม่รองรับ WebGL และการรองรับมือถือ:** ตามที่ระบุในหัวข้อกรณีขอบ
